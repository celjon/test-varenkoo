# Mini-CRM для распределения лидов

Сервис автоматического распределения обращений клиентов между операторами с учетом источников и весовых коэффициентов.

## Запуск

### Обычный запуск
```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

### Запуск с Docker
```bash
docker-compose up --build
```

API: http://localhost:8000
Документация: http://localhost:8000/docs

## Модель данных

### Operator
- `name` - имя оператора
- `is_active` - может ли получать обращения
- `max_load` - максимальное количество активных обращений
- `current_load` - текущая нагрузка (контакты со статусом != 'closed')

### Source
- `name` - название источника (telegram_bot_1, web_form и т.д.)
- `description` - описание

### Lead
- `external_id` - внешний идентификатор
- `phone` - телефон
- `email` - email
- `name` - имя клиента

Лид идентифицируется по приоритету: external_id → phone → email. При создании контакта система автоматически находит существующего лида или создает нового.

### Contact
- `lead_id` - лид
- `source_id` - источник обращения
- `operator_id` - назначенный оператор (может быть NULL)
- `status` - new / in_progress / closed
- `message` - текст обращения

### OperatorSourceWeight
Настройка весов операторов для каждого источника. Определяет вероятность назначения.

## Алгоритм распределения

При создании контакта через `POST /contacts`:

1. Находим или создаем лида по идентификатору
2. Проверяем существование источника
3. Получаем операторов для этого источника и фильтруем:
   - `is_active = True`
   - `current_load < max_load`
4. Выбираем оператора случайным образом с учетом весов: вероятность = weight / sum(weights)
5. Создаем контакт с назначенным оператором

Если подходящих операторов нет, контакт создается с `operator_id = NULL` (без ошибки).

**Пример весов:**
- Оператор A: weight = 3 → вероятность 60%
- Оператор B: weight = 2 → вероятность 40%

## API

### Операторы

**POST /operators**
```json
{
  "name": "Иван Петров",
  "is_active": true,
  "max_load": 10
}
```

**GET /operators** - список операторов с текущей нагрузкой

**PATCH /operators/{id}** - обновить статус или лимит
```json
{
  "is_active": false,
  "max_load": 15
}
```

### Источники

**POST /sources**
```json
{
  "name": "telegram_bot_1",
  "description": "Основной Telegram бот"
}
```

**POST /sources/{id}/weights** - настроить веса для операторов
```json
{
  "weights": [
    {"operator_id": 1, "weight": 3.0},
    {"operator_id": 2, "weight": 2.0}
  ]
}
```

### Контакты

**POST /contacts** - создать обращение с автоматическим распределением
```json
{
  "source_name": "telegram_bot_1",
  "phone": "+79991234567",
  "name": "Анна Иванова",
  "message": "Здравствуйте, интересует ваш продукт"
}
```

Обязательно указать хотя бы один идентификатор: external_id, phone или email.

### Просмотр данных

**GET /leads** - список лидов с их обращениями

**GET /leads/statistics** - статистика распределения по операторам и источникам

## Архитектура

- `models.py` - SQLAlchemy модели
- `schemas.py` - Pydantic схемы валидации
- `services.py` - бизнес-логика распределения
- `api/` - HTTP эндпоинты
- `database.py` - настройка БД

## Тестирование

Проект включает 14 unit-тестов, покрывающих основной функционал.

```bash
pip install -r requirements-dev.txt
pytest tests/ -v
```

Тесты проверяют:
- Создание и управление операторами
- Настройку источников и весов
- Логику распределения контактов
- Работу с лидами и статистику
- Граничные случаи (неактивные операторы, превышение лимита)
